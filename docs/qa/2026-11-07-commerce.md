## Scope of evidence

The resolver baseline was evaluated by loading its source at f541a05 into the same scenario suite. Cases COM-02 and COM-03 fail on the baseline and pass on the candidate.

Browser tests use the real Next.js product route and rendered components at 390px width with an artificial signed-in buyer. Merchant availability, checkout response, Supabase reads and the native browser bridge are fixtures. They verify interaction and routing, without placing an order or testing a physical native controller.

A native/server hydration warning was observed while developing the browser fixtures and is tracked as UX-3. An early test fixture incorrectly returned arrays for database single-object reads, causing a review-card failure. The fixture now distinguishes those responses. These are recorded separately from the four passing task scenarios.

## Next comparison

Keep the same scenario IDs and add real provider-contract fixtures when integrating Checkout Kit or Universal Checkout. Record capability access and physical-device observations separately. Candidate visual or performance improvements must preserve these outcomes and add evidence for the specific task being improved.

## Merchant checkout parity

ADR 0007 covers the continuation from eaf5d31. The real already-running iPhone 18 Pro Max was used as requested, without a Simlock device. Its sticky Buy dialog was clipped below the screen. COM-PARITY-05 reproduces that exact entry point against the baseline component and fails because its bottom is 1125px in an 844px viewport. The candidate document portal passes the same geometry check and reaches SDK presentation with quantity two.

Five offline scenarios cover direct Shopify checkout without variant metadata, browser-only merchant pages, SDK errors without automatic fallback, insecure destinations and synchronous web popup opening. Seven browser scenarios cover those product paths, the absence of unused session requests, Escape during native presentation, sticky Buy geometry, a slow inventory response and insecure-link recovery.

The first candidate full browser run passed 25/25 before the slow-inventory and insecure-link cases were added. The six parity cases including the eight-second inventory timeout passed together. Final candidate totals are 22/22 offline commerce cases and 27/27 browser scenarios. TypeScript, changed-source ESLint and the three native registration checks pass. Native production verification follows deployment.

The live Naked Nutrition product endpoint returned HTTP 200, variant 1248822167 available, price 3599 cents. No order or payment was submitted. Native release verification must distinguish a visible merchant checkout from a completed purchase.

After integrating concurrent main changes, the full local suite passed 81/81 Chromium scenarios. The first remote run passed 80/81 and caught two profile social-link inputs overflowing the 320px viewport by 3px. Both flex children now use `min-w-0`; the same profile control evaluation passes at 320px, 768px and 1440px. This recovery is included so release checks cover the combined code.
