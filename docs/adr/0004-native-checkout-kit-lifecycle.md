# ADR 0004 — Native Checkout Kit owns a presentation outcome

Date November 7, 2026. Status accepted for the single-merchant product checkout integration.

## Decision

Use Shopify Checkout Kit 4.0.0 through a local Capacitor plugin. Pin the SDK in the Xcode project directly, keeping it outside the package manifest regenerated by Capacitor sync.

Each presentation owns its delegate and pending bridge call. A second presentation is rejected while one is open. Only the SDK completion callback records completion. Failure cannot erase a recorded completion. Closing a sheet without either outcome returns dismissed. Dismissal settles the bridge promise and releases the presentation, allowing an explicit retry.

Return only the outcome to JavaScript. Do not relay buyer details, checkout snapshots, payment data or session URLs through diagnostic events. Disable optional SDK diagnostic telemetry.

The review panel displays a pending state while native checkout is open. It shows completion only after the native callback outcome. Dismissal restores the review action, and failure offers recovery without automatically reopening checkout. A generation guard prevents an old promise from changing a newly opened review panel.

Existing installed binaries that lack the plugin retain Capacitor Browser presentation. A present plugin that fails is not silently retried in another surface.

## Integration

- The root Capacitor class list and sync restoration both include SuppStackCheckoutPlugin.
- The SDK is pinned to 4.0.0 in the Xcode project and Swift resolution file.
- The JavaScript adapter rejects insecure URLs and unknown result states.
- Physical-product checkout uses the native SDK. Multi-merchant orchestration and grouped stack presentation remain future milestones.
- The auth gate uses the server's public-web snapshot during hydration, then applies native route rules. Private routes remain blocked while auth loads.

## Evidence and remaining checks

Offline commerce evaluations pass 11/11. Browser evaluations pass 9/9, covering the existing browser fallback, selected quantity, completion, dismissal/retry, terminal failure, unknown outcome, simultaneous clicks and sign-in noise. Native fixtures assert that hydration produces no warning.

The iOS simulator target compiles with Checkout Kit. Simulator launch is a smoke test only. Physical iPad/iPhone checkout, Shop Pay challenges, merchant receipts and external payment-app return remain required before claiming device payment verification.

The SDK requirements and callback contract are documented in [Shopify Checkout Kit](https://shopify.dev/docs/storefronts/mobile-next/checkout-kit) and its [lifecycle guide](https://shopify.dev/docs/storefronts/mobile-next/checkout-kit/monitor-checkout-lifecycle).
